# AI Agent Session 隔離策略

## 1. 問題本質

### 傳統 Clean Room 的物理隔離

```
規格編寫者房間（可看原程式碼）
        ↓ 規格文件（紙質）
        ↓ 物理傳遞
移植開發者房間（不可看原程式碼）
```

物理隔離確保：移植開發者**無法接觸**原始程式碼。

### AI Agent 的資訊隔離挑戰

```
AI Agent 的上下文記憶
├── Session 內記憶（對話歷史）
├── 跨 Session 記憶（MemPalace）
└── 模型訓練資料（隱性記憶）
```

問題：AI Agent 在 Session A 看了原程式碼，Session B 可能「記得」。

## 2. 三層隔離策略

### Layer 1: Session 隔離（顯式上下文）

| 策略 | 操作 | 效果 |
|------|------|------|
| **新 Session** | 每個階段開啟新對話 | 清除對話歷史 |
| **不攜帶文件** | Session B 不打開原程式碼文件 |無法讀取原程式碼 |
| **只看規格** | Session B 只讀取 `/raw/specs/*.md` | 資訊來源受限 |

```
Session A（規格提取）
─────────────────────
輸入：原程式碼倉庫
操作：提取功能，不複製程式碼
輸出：/raw/specs/*.md
結束：關閉 Session，不記錄程式碼細節到 MemPalace

Session B（新實現）
─────────────────────
輸入：/raw/specs/*.md（只有規格）
操作：根據規格寫新程式碼
輸出：新語言實現
限制：不打開原程式碼文件
```

### Layer 2: MemPalace 記錄策略（跨 Session 記憶）

**關鍵規則**：MemPalace 只記錄**規格內容**，不記錄**程式碼細節**。

| 可記錄 | 不可記錄 |
|--------|----------|
| 功能描述 | 具體程式碼片段 |
|輸入/輸出格式 |變數命名 |
| 邊界條件 | 算法細節（如迴圈結構） |
| 模組名稱 | 實現技巧 |

**MemPalace 記錄示例（正確）**：
```
SESSION:2026-04-27|PROJ:CRD|SPEC:日誌模組|FUNC:寫入日誌到文件|INPUT:msg(string),level(enum)|OUTPUT:void|BOUNDARY:空msg→skip|★★★
```

**錯誤示例（洩漏程式碼）**：
```
SESSION:2026-04-27|PROJ:CRD|CODE:if(msg==null)return;File.write(msg);|★★★
```

### Layer 3: 規格文件的自我審查

規格文件編寫後，需檢查是否洩漏實現細節：

| 檢查項 | 問題示例 | 修正 |
|--------|----------|------|
| **算法結構** | 「用雙重迴圈遍歷」 | → 「遍歷直到有序」 |
| **變數命名** | 「變數 `n` 存陣列長度」 | → 「取得陣列長度」 |
| **語言特性** | 「用 `[a,b] = [b,a]` 交換」 | → 「交換兩元素」 |
| **程式碼片段** | 包含任何程式碼區塊 | → 刪除，用自然語言描述 |

## 3.實際操作流程

### Phase 1: 規格提取（Session A）

```
使用者指令：
「我有一個 JS專案，幫我提取功能規格到 /raw/specs/」

AI 行為：
1.讀取原程式碼倉庫
2. 提取功能描述（自然語言）
3. 編寫規格文件 → /raw/specs/*.md
4. 記錄到 MemPalace（只記錄功能，不記錄程式碼）
5. 結束 Session，建議使用者開啟新 Session

AI輸出：
「規格已提取到 /raw/specs/。請開啟新 Session進行實現，
 並告訴我『根據 /raw/specs/實現 C#版本』。」
```

### Phase 2: 新實現（Session B）

```
使用者指令：
「根據 /raw/specs/實現 C#版本」

AI 行為：
1.讀取 /raw/specs/*.md（只有規格）
2. 不打開原程式碼文件
3. 根據規格寫 C# 實現
4. 編寫測試用例（根據規格的輸入/輸出）

AI 限制：
- 即使 MemPalace 有記錄，也不主動查詢原程式碼細節
- 如果規格不完整，向使用者提問而非回看原程式碼
```

### Phase 3: 測試驗證（Session C）

```
使用者指令：
「驗證 C#實現是否符合規格」

AI 行為：
1. 執行測試用例
2.對比輸入/輸出行為
3. 報告差異（如有）
4. 不對比程式碼結構
```

## 4. MemPalace 配合 Clean Room 的配置

### Wing 架構調整

```
wing: wing_clean_room_design
├── room: specs/           ← 功能規格（Session A輸出）
├── room: implementations/ ← 新實現記錄（Session B輸出）
├── room: test-results/    ← 測試驗證（Session C輸出）
└── room: decisions/       ← 移植決策記錄
```

### 記錄規則（寫入 AGENTS.md）

```markdown
## Clean Room 記錄規則

1. **規格階段**：只記錄功能描述，不記錄程式碼
2. **實現階段**：可記錄實現決策，不對比原程式碼
3. **驗證階段**：只記錄測試結果，不分析程式碼差異
```

## 5. 風險與應對

### 風險 1: AI 隱性記憶

AI 模型的訓練資料可能包含類似程式碼。

**應對**：
-無法完全消除（模型固有特性）
-規格盡量抽象，減少與訓練資料的關聯
- 法律上仍需律師確認

### 風險 2: 規格遺漏關鍵功能

新實現可能缺少原程式碼的功能。

**應對**：
-規格階段詳細審查
- 測試階段用原程式碼的真實用例驗證
-發現遺漏時，回到規格階段補充（不直接看程式碼）

### 風險 3: MemPalace 汙染

Session A 的程式碼細節可能被記錄到 MemPalace。

**應對**：
- Session A結束前，審查 MemPalace記錄
- 使用 `mempalace_kg_invalidate` 清除程式碼細節記錄

```
│  ─────────────────────────────────  │
│  讀取：原程式碼倉庫                     │
│輸出：/raw/specs/*.md               │
│  記錄：MemPalace（功能描述）          │
│  檢查：不記錄程式碼細節                 │
│  結束：建議使用者開新 Session           │
└─────────────────────────────────────┘
              ↓ 新 Session
              ↓ 不攜帶原程式碼文件
┌─────────────────────────────────────┐
│  Session B: 新語言實現                │
│  ─────────────────────────────────  │
│  讀取：/raw/specs/*.md               │
│限制：不打開原程式碼文件               │
│輸出：新語言程式碼                     │
│  記錄：實現決策（不對比原程式碼）        │
└─────────────────────────────────────┘
              ↓ 新 Session
┌─────────────────────────────────────┐
│  Session C: 測試驗證                  │
│  ─────────────────────────────────  │
│輸入：原程式碼測試用例                  │
│  執行：新實現測試                     │
│  對比：輸入/輸出行為                  │
│  報告：差異（如有）                   │
└─────────────────────────────────────┘
```
